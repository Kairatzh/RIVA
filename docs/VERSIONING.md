## Политика версионирования RIVA DSL

Версия документа: 0.1.0  
Статус: черновик

### 1. Уровни версий

Используется семантическое версионирование формата `MAJOR.MINOR.PATCH` для двух независимых сущностей:

- **Версия языка (DSL)** — описывает синтаксис и семантику RIVA DSL.
- **Версия рантайма/исполнителя** — описывает реализацию интерпретатора/движка.

В дальнейшем также может вводиться версия отдельных workflow‑шаблонов.

### 2. Семантическое версионирование

- **MAJOR** (мажорная версия):
  - несовместимые изменения в синтаксисе DSL;
  - удаление или радикальное изменение поведения ключевых конструкций;
  - отказ от ранее поддерживаемых файловых форматов.

- **MINOR** (минорная версия):
  - добавление новых конструкций и полей без нарушения обратной совместимости;
  - расширение возможных значений существующих атрибутов;
  - улучшения, не требующие миграции существующих сценариев.

- **PATCH** (патч‑уровень):
  - уточнения документации;
  - исправление неоднозначностей спецификации;
  - редакторские правки, не меняющие поведение.

### 3. Пометка версий в репозитории

- Основная версия DSL указывается в:
  - `README.md` (кратко);
  - `docs/OVERVIEW.md` и `docs/LANGUAGE_REFERENCE.md` (детально в заголовках).
- Версии рантайма и инструментов будут фиксироваться дополнительно в:
  - `RUNTIME_VERSION.md` (планируется);
  - тегах репозитория (Git tags), например `dsl-v1.0.0`, `runtime-v1.0.0`.

### 4. Управление изменениями языка

Для любых изменений DSL:

1. **Описание предложения**  
   - краткое описание мотивации;
   - влияние на существующие сценарии;
   - пример до/после.

2. **Обсуждение**  
   - в трекере задач (Issues) и/или RFC‑документах;
   - согласование уровня версии (MAJOR/MINOR/PATCH).

3. **Реализация**  
   - обновление спецификации в `docs/LANGUAGE_REFERENCE.md`;
   - добавление/обновление примеров в `examples/`;
   - при необходимости — добавление миграционных заметок.

4. **Выпуск релиза**  
   - присвоение нового номера версии;
   - обновление упоминаний версии во всех актуальных документах;
   - описание изменений в отдельном файле журнала изменений.

### 5. Журнал изменений

Для отслеживания истории будет использоваться файл журнала, например `CHANGELOG.md` (планируется). Структура записей:

- заголовок с номером версии и датой;
- разделы:
  - `Added` — добавлено;
  - `Changed` — изменено;
  - `Deprecated` — помечено к удалению;
  - `Removed` — удалено;
  - `Fixed` — исправлено;
  - `Security` — изменения, связанные с безопасностью.

### 6. Депрекации и миграции

- Любое планируемое удаление конструкции в будущем мажорном релизе должно:
  - быть заранее задокументировано;
  - иметь переходный период, в котором конструкция помечена как `deprecated`;
  - сопровождаться рекомендациями по миграции.

- Инструменты миграции (CLI или скрипты) будут проектироваться отдельно, но подход к ним будет описан в документации к рантайму.

### 7. Текущий статус

- Текущая версия концепции DSL: `0.1.0` (проектирование, без реализации рантайма).
- Внесение существенных изменений на этом этапе возможно, но должно сопровождаться обновлением данного документа и справочника языка.
