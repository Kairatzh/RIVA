## Обзор RIVA DSL

Версия документа: 0.1.0  
Статус: черновик спецификации (Draft)

### Цели проекта

- **Простой язык для сложных LLM‑воркфлоу**: RIVA DSL позволяет описывать многошаговые пайплайны, мультиагентные сценарии и работу с внешними источниками в человеко‑читаемом виде.
- **Доступен людям без опыта программирования**: синтаксис и ключевые концепции ориентированы на понятные термины и естественный язык, а не на низкоуровневую логику.
- **Встроенный “мини‑ИИ” внутри языка**: специальная семантика `auto` позволяет делегировать промпт‑инжиниринг, выбор схем данных, разбиение на шаги и другие технические детали встроенному помощнику.
- **Фокус на reproducibility и версионировании**: каждая версия DSL и сценариев должна быть воспроизводимой, с явным управлением изменениями.

### Базовые принципы дизайна

- **Декларативность**: пользователь описывает “что надо сделать”, а не “как именно это реализовано”.
- **Явные сущности домена**:
  - `workflow` — полный сценарий работы;
  - `step` — отдельный шаг с моделью или действием;
  - `agent` — роль/персонаж, основанный на модели;
  - `data` — входные и выходные данные (text, json, table, file и т.д.).
- **Минимум ключевых слов, максимум естественного языка**: описания намерений (`intent`) и целей (`goal`) пишутся обычным языком, который интерпретирует LLM.
- **Безопасная эволюция**: изменения DSL должны быть совместимы по умолчанию; несовместимые изменения требуют мажорного релиза и миграционной истории.

### Высокоуровневая модель

1. **Workflow**  
   Описывает полный процесс как набор шагов, моделей и внешних источников.

2. **Steps**  
   Каждый шаг выполняет одну понятную задачу:
   - генерация контента (текст, код, таблицы, JSON);
   - трансформация данных (очистка, форматирование, конвертация);
   - анализ и извлечение информации (классификация, суммаризация, NER);
   - инфраструктурные операции (логирование, оценка стоимости, кеширование).

3. **Мини‑ИИ (`auto`)**  
   Специальное ключевое слово для делегирования части настроек языку:
   - конструкция промпта для модели;
   - определение схем JSON/таблиц;
   - проектирование цепочек (chaining) из нескольких шагов;
   - стратегии ретраев и валидации.

4. **Контроль потока**  
   Высокоуровневые конструкции:
   - последовательное выполнение шагов;
   - условные ветвления;
   - параллельные блоки;
   - декларативное описание циклов.

### Целевая аудитория

- создатели LLM‑продуктов и сценариев без глубоких навыков программирования;
- продакт‑менеджеры и аналитики, описывающие процессы на уровне “что должно происходить”;
- инженеры, которым нужен централизованный, читаемый и версионируемый формат описания пайплайнов.

### Что входит в репозиторий

- `README.md` — краткий обзор проекта и статуса;
- `docs/OVERVIEW.md` — текущий документ с концептуальным обзором;
- `docs/LANGUAGE_REFERENCE.md` — справочник по синтаксису и ключевым конструкциям DSL;
- `docs/VERSIONING.md` — политика версионирования и правила изменений;
- `docs/LEARNING.md` — обучение и постепенный гид для новых пользователей;
- `examples/` — набор готовых примеров workflow на RIVA DSL.
