## Обучающий гид по RIVA DSL

Версия документа: 0.1.0  
Цель: помочь пользователям без опыта программирования начать использовать RIVA DSL для описания LLM‑воркфлоу.

---

### 1. Что такое RIVA DSL

RIVA DSL — это текстовый формат, в котором вы описываете:

- какие задачи должна решать модель (или несколько моделей);
- какие шаги должны выполняться последовательно;
- какие данные подаются на вход и что получается на выходе.

Вы не пишете программный код, а описываете сценарий понятными словами. Затем интерпретатор RIVA (рантайм) будет исполнять этот сценарий, обращаясь к LLM‑моделям и внешним источникам.

---

### 2. Минимальный словарь терминов

- **Workflow** — сценарий целиком (как бизнес‑процесс или пайплайн).
- **Step** — один шаг сценария (например, “написать статью”, “сделать краткое резюме”).
- **Model** — конкретная LLM‑модель (например, gpt‑4.1).
- **Agent** — роль на основе модели (например, “писатель”, “критик”).
- **Input / Output** — входные и выходные данные workflow.
- **auto** — специальное слово, означающее “пусть встроенный ИИ поможет сконструировать детали”.

---

### 3. Первый пример: генерация и краткое резюме статьи

Сценарий: пользователь задает тему, система генерирует статью и делает к ней краткое резюме.

Файл `examples/article_basic.riva`:

```yaml
workflow article_basic:
  description: "Простой пайплайн: статья + краткое резюме"

  models:
    writer: gpt-4.1
    analyzer: gpt-4.1-mini

  inputs:
    topic: text

  outputs:
    article_text: text
    summary_text: text

step generate_article:
  model: writer
  kind: text.generate
  intent: auto "Написать понятную статью по теме {topic} для широкой аудитории"
  output: article_text

step summarize_article:
  model: analyzer
  kind: text.summarize
  input:
    - article_text
  output: summary_text
```

Объяснение:

- в блоке `workflow` мы описали название, модели и перечень входов/выходов;
- шаг `generate_article` создает основную статью;
- шаг `summarize_article` делает краткое резюме на основе сгенерированной статьи.

---

### 4. Шаг за шагом: как придумывать workflow

1. **Опишите задачу словами**  
   Например: “Мне нужно автоматически получать статьи по теме и резюме для отчета руководству”.

2. **Найдите сущности**  
   - вход: тема статьи (`topic`);
   - промежуточный результат: полный текст статьи (`article_text`);
   - итоговый результат: краткое резюме (`summary_text`).

3. **Разбейте на шаги**  
   - шаг 1: сгенерировать статью;
   - шаг 2: сделать резюме.

4. **Пропишите шаги в DSL**  
   - выберите модель;
   - сформулируйте `intent` на естественном языке, можно с `auto`.

---

### 5. Второй пример: мультиагентный сценарий “писатель + критик”

Цель: сначала черновик статьи, потом критика и улучшение текста.

Файл `examples/article_multi_agent.riva`:

```yaml
workflow article_multi_agent:
  description: "Писатель и критик совместно создают улучшенную статью"

  agents:
    writer:
      model: gpt-4.1
      role: "Пишет статьи"
    critic:
      model: gpt-4.1-mini
      role: "Оценивает и предлагает улучшения"

  inputs:
    topic: text

  outputs:
    draft: text
    improved_article: text

step write_draft:
  agent: writer
  kind: text.generate
  intent: auto "Написать черновик статьи по теме {topic}"
  output: draft

step review_draft:
  agent: critic
  kind: text.generate
  input:
    - draft
  intent: auto "Дай список конкретных рекомендаций, как улучшить этот текст"
  output: review_notes

step improve_article:
  agent: writer
  kind: text.generate
  input:
    - draft
    - review_notes
  intent: auto "Улучшить черновик с учетом всех рекомендаций"
  output: improved_article
```

Этот пример показывает:

- как объявить агентов с ролями;
- как организовать взаимодействие “писатель → критик → писатель”.

### 6. Третий пример: работа с внешними данными (заголовки из API)

Сценарий: загрузить список новостей по API и сделать сводку.

Файл `examples/news_summary.riva`:

```yaml
workflow news_summary:
  description: "Обзор новостных заголовков и краткая сводка"

  models:
    summarizer: gpt-4.1-mini

  outputs:
    headlines_text: text
    summary_text: text

step fetch_news:
  from:
    url: "https://example.com/api/news"
    method: GET
  output: headlines_json

step format_headlines:
  model: summarizer
  kind: text.generate
  input:
    - headlines_json
  intent: auto "Преобразуй JSON со списком новостей в удобный для чтения список заголовков"
  output: headlines_text

step summarize_headlines:
  model: summarizer
  kind: text.summarize
  input:
    - headlines_text
  output: summary_text
```

---

### 7. Рекомендации для написания собственных сценариев

- **Начинайте с текста, а не с кода**: сначала напишите обычным языком, что нужно сделать и в каком порядке.
- **Используйте говорящие имена**: `generate_article`, `summarize_article`, `fetch_news` и т.д.
- **Не бойтесь слова `auto`**: сформулируйте цель шага максимально понятно, а детали промпта передайте встроенному ИИ.
- **Разбивайте сценарий на маленькие шаги**: лучше 3–4 простых шага, чем один перегруженный.
- **Добавляйте описания**: заполняйте `description` в `workflow`, это поможет другим понять идею.

---

### 8. Дальнейшие шаги обучения

После освоения базовых примеров рекомендуется:

1. Изучить справочник `docs/LANGUAGE_REFERENCE.md` для понимания всех доступных конструкций.
2. Создать собственный workflow для своей задачи (например, генерация отчетов, подготовка писем, анализ обратной связи).
3. Постепенно добавлять:
   - больше шагов;
   - мультиагентные взаимодействия;
   - работу с внешними источниками;
   - контрольные условия (например, отправка уведомлений при определенных ключевых словах).

Реализация рантайма и исполняющей логики будет описана в отдельных документах и не входит в текущий обучающий материал.
